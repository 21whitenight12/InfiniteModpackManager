## WPF-UI 4.3.0 / .NET 10 API-факты (проверено по XML-докам пакетов, не по памяти)
- **Полный проверенный API-слой — скилл `wpf-ui-lepoco`** (namespace'ы сервисов, ContentDialog/Snackbar/NavigationView wiring из Gallery, иконки, грабли); ниже — только дополнения, специфичные для IMM.
- FluentWindow: `WindowBackdropType="Auto"`; свойства `FallbackColor` в 4.x НЕТ (Win10 деградацию делает сам Auto)
- `IContentDialogService`/`ISnackbarService` — namespace `Wpf.Ui` (НЕ `Wpf.Ui.Abstractions`); DI-интерфейсы брать оттуда
- Диалоги: хост в XAML — `ui:ContentDialogHost` (устаревший путь — ContentPresenter); `SetDialogHost(ContentDialogHost)` без warning
- `ShowSimpleDialogAsync` — extension из `Wpf.Ui.Extensions`, принимает `SimpleContentDialogCreateOptions { Title, Content, CloseButtonText }`
- `AddSerilog()` для ILoggingBuilder — отдельный пакет `Serilog.Extensions.Logging`
- `dotnet new sln` в .NET 10 по умолчанию создаёт `.slnx` — классика: `--format sln`
- В WPF-проекте `System.IO` не входит в implicit usings — нужен явный `using System.IO;`
- `SymbolRegular` НЕ содержит Gamepad* — иконки проверять по бинарю пакета до использования; несуществующая иконка в DataTemplate = краш рендера (шторм FTL без лимита лога → гигабайты; лимит 20МБ настроен)
- WPF: `Page` можно хостить только в `Frame`/`Window` — в ContentControl падает при рендере
- XAML: не instantiate'ить DI-зависимые Page в XAML — только code-behind (конструктор с параметрами → NRE биндера)
- Fatal до конца старта: `Handled=true` оставляет зомби-процесс — нужен `Shutdown(1)` по флагу `_startupCompleted`
- VMGenerator: `[ObservableProperty]`/`[RelayCommand]` требуют явных usings CommunityToolkit.Mvvm.*; partial-методы `OnXxxChanged` — только при наличии генераторного объявления
